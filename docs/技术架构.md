# PeriNest 技术架构体系化文档

**项目代号**：PeriNest（蜚蠊巢穴）
**Slogan**：*Built to Survive, Designed to Adapt.*（为生存而生，为适应而设计。）
**版本**：v1.0
**更新日期**：2026-09-04
**部署基线**：原生 Python 虚拟环境 + Systemd/Supervisor 进程守护 + Nginx 反向代理（无 Docker）

---

## 1. 项目概述

### 1.1 架构愿景
PeriNest 是一套面向**高可用、敏捷响应**的多端企业级应用架构。以"蜚蠊"这一古老且生存力极强的生物为灵感，强调系统在复杂网络环境、高并发流量下的**韧性（Resilience）**与**自适应（Adaptability）**。

### 1.2 核心生态角色映射

| 终端 | 代号 | 角色隐喻 | 核心职责 |
| :--- | :--- | :--- | :--- |
| **后端核心** | **Queen（虫母）** | 巢穴心脏 | 业务逻辑裁决、数据状态管理、对外输出统一 API。稳如磐石，确保数据强一致。 |
| **Web 前端** | **Wing（翅翼）** | 广阔视界 | PC 端管理后台/企业官网。负责大屏数据可视化、复杂表单交互、运营配置。 |
| **小程序端** | **Antenna（触角）** | 灵敏探针 | 微信生态内轻量化服务。负责扫码、LBS 定位、快捷支付、即时消息推送。 |
| **H5 移动端** | **Leg（足）** | 六足爬行 | 移动浏览器直达的轻应用。免安装、免小程序审核，分享链接即达，覆盖微信外流量。 |
| **AI 网关** | **Nerve（神经索）** | 神经传导 | OpenAI 兼容多 provider 统一接入，SSE 流式，mock 模式零成本。 |
| **MCP 服务** | **Spiracle（气门）** | 呼吸交换 | MCP 协议端点，把业务能力暴露为 AI 客户端可调用的工具。 |

## 4. 后端核心 设计规范

### 4.1 分层架构（严守依赖倒置）

- **API 层**：只负责接收请求、参数校验（Pydantic）、调用 Service、返回 Response。**禁止**编写业务 SQL 或复杂逻辑。
- **Service 层 (Queen 决策大脑)**：承载全部业务规则、事务管理（利用 SQLAlchemy 上下文）、调用第三方 SDK。
- **Model 层**：纯表结构定义，**禁止**包含业务方法（贫血模型）。
- **Schema 层**：定义接口契约，使用 Pydantic `model_validator` 实现跨字段校验。

### 4.2 核心配置规范

所有配置通过环境变量注入，区分开发/测试/生产环境。启动时加载 `.env` 文件。环境变量前缀 `PERINEST_Q_`。

### 4.3 数据库表命名规范

统一前缀 `pn_`，后接模块名：

- `pn_user` (用户表)
- `pn_order` (订单表)
- `pn_order_item` (订单明细)
- `pn_sys_log` (系统日志)

### 4.4 异步事务处理准则

- 使用 `async SQLAlchemy` + `aiomysql`。
- 在 Service 层使用 `@contextlib.asynccontextmanager` 管理 Session 生命周期。
- **避免**在 FastAPI 路由中直接使用 `time.sleep()`，必须使用 `asyncio.sleep()` 避免阻塞事件循环。

## 5. 四端联调与契约规范

### 5.1 契约来源：OpenAPI (Swagger)

Queen 启动 FastAPI 后，自动生成 `/docs` 和 `/openapi.json`。**以 Queen 为唯一数据源**。

### 5.2 类型安全的端到端体验

- **Wing / Leg (Web/H5)**：使用 `openapi-typescript` 将 `/openapi.json` 转换为 TypeScript 类型文件。
- **Antenna (小程序)**：开发时参考生成的类型定义，手动定义 `interface`。

### 5.3 时间规范

所有时间字段后端统一使用 **ISO 8601** 格式返回，前端使用 `dayjs` 进行时区转换展示。

## 6. 环境配置与部署方案 (无 Docker)

### 6.1 环境划分

| 环境 | 代号 | 用途 |
| :--- | :--- | :--- |
| **开发环境** | **Egg (卵)** | 开发者本地 PC，直连测试库。 |
| **测试环境** | **Nymph (若虫)** | 内部测试/QA 验证，部署在内网服务器。 |
| **预发布环境** | **Pupa (蛹)** | 预演正式发布流程，连接预发布 DB，使用生产配置但隔离流量。 |
| **生产环境** | **Imago (成虫)** | 最终对外服务。 |

### 6.2 后端 部署流程（原生 Python）

1. 代码同步 → release 分支
2. `python3.11 -m venv .venv && poetry install`
3. 写入生产 `.env`
4. `alembic upgrade head`
5. Gunicorn 多进程管理 Uvicorn Worker：`gunicorn -c gunicorn.conf.py app.main:app`
6. Supervisor/Systemd 守护（断头再生）

### 6.3 Nginx (Carapace 背甲) 配置要点

- SSL 终结、动静分离（/static 直读文件系统）、`/api` 转发 127.0.0.1:8000、`limit_req_zone` 限流。

### 6.4 前端部署

- **Wing**：`npm run build` → dist → Nginx html 目录。
- **Antenna**：微信开发者工具上传 → 公众平台提审发布。

## 7. 非功能需求与监控

| 特性 | 实现方案 |
| :--- | :--- |
| **高可用** | Gunicorn 多 Worker + Supervisor 自动重启；数据库主从同步。 |
| **缓存策略** | Redis 缓存热数据（配置、权限树），TTL 动态设置。 |
| **日志追踪** | `structlog` 输出 JSON 日志，接入 ELK/Loki，每 Request 注入唯一 `trace_id`。 |
| **隐私默认** | Nerve 对话无状态不落库、不上报；将来加会话留存时，默认同样关闭，仅用户显式反馈动作才授权带走当前会话（FEEDBACK_ONLY 模式）。 |
| **性能压测** | Locust 模拟 Antenna 并发请求 Queen。 |

## 9. 共生体原则：AI 是一等公民

> 蜚蠊体内有真实的共生菌群：以宿主摄取的食物为食，替宿主完成消化。
> PeriNest 的 AI 同理——**以授权用户的身份行事，替用户完成工作。**

AI Native 不是"系统里有个 AI 入口"，而是系统对 AI 主体友好：

### 9.1 AI 友好五原则

| # | 原则 | 落地机制 |
|:---|:---|:---|
| 1 | **能力对称**：用户在 REST 上的每个能力，AI 经 MCP 同样具备 | `tests/test_capability_parity.py` 强制对账，缺口 CI 红 |
| 2 | **权限同源**：AI 的权限边界 = 授权用户的边界，永不放大 | MCP 与 REST 共用 `CurrentUser` + 同一 Service 层，权限逻辑只写一次 |
| 3 | **机器可读**：接口即文档，错误即数据 | OpenAPI 完备；越权返回结构化 `{"denied": true, "reason": ...}` 而非静默降级 |
| 4 | **自描述**：AI 能自己发现"我能做什么" | MCP `initialize` 声明 symbiont 语义；`tools/list` 即能力清单 |
| 5 | **归属明确**：AI 的一切行为落在授权用户名下 | 代下单归属本人、反馈署名本人（`tests/test_symbiont.py` 验证） |

### 9.2 新接口开发 checklist（每加一个端点都要过）

1. 这个能力 AI 需要吗？
   - 需要 → 同步加 MCP 工具，登记 `PARITY_MAP`
   - 不需要 → 登记 `EXEMPT` 并写明理由（理由不充分 = 破坏原则）
2. 权限逻辑写在 **Service 层**（一处定义，REST/MCP 两端复用，禁止端点各自实现）
3. MCP 工具 description 写明权限语义（如"仅授权用户可见范围"）——工具描述就是 AI 的说明书
4. 补两类测试：能力对称（parity 自动覆盖）+ 权限一致性（照 `test_symbiont.py` 模板）

> 忘了任何一步，CI 会红给你看。原则不是文档，是测试。
