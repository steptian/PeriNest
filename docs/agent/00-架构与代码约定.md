## 分层铁律（✅ `queen/app/` 目录结构）

1. **API 层**（`queen/app/api/v1/endpoints/`）只做收发：参数校验→调 service→返回。禁写业务 SQL
2. **Service 层**（`queen/app/services/`）承载全部业务规则——**权限逻辑只写在这里**（共生体原则要求 REST/MCP 复用同一份）
3. **Model 层**（`queen/app/models/`）贫血模型，纯表结构，表名前缀 `pn_`（✅ `queen/app/models/user.py:11`）
4. **Schema 层**（`queen/app/schemas/`）request/response 契约，跨字段校验用 `model_validator`

## 版本管理（单一源）

- **唯一版本源**：根 `VERSION` 文件
- Queen 运行时读它：`queen/app/core/config.py:15`（read_repo_version，回退内置）
- Wing/Leg 构建期注入：`wing/vite.config.ts:7` / `leg/vite.config.ts`（define `__APP_VERSION__`）
- Antenna 读不到仓库文件，**手动同步** `antenna/miniprogram/app.ts`
- `queen/pyproject.toml` 静态 version，CI 有一致性校验（`.github/workflows/ci.yml` Version consistency 步骤）
- 发版三步：改 VERSION（+3 处同步）→ CHANGELOG 加条目 → `git tag vX.Y.Z && git push --tags`
- 坑：setuptools 不支持 dynamic version 指向上级目录（`../VERSION` 会炸构建）ℹ️

## 设计系统（琥珀标本馆，三端同源）

- 令牌定义：`wing/src/index.css` 与 `leg/src/index.css`（变量集一致：--primary 琥珀金/--card 纸面/--border 树脂线）
- 暗色分层策略：**表面亮度差 + 环境阴影**替代亮描边（`.dark` 块，✅ `leg/src/index.css:33`）——用户反馈"黑底边线突兀"后确立
- 衬线：Fraunces（拉丁）+ 系统宋体栈，class `font-specimen`；图鉴小字 `specimen-latin`
- Antenna 用 wxss 平行实现（`antenna/miniprogram/app.wxss`，无 webfont，系统衬线栈）
