# 03 · 部署与 CI

**关键词索引**：无 Docker / Systemd / Nginx / deploy.sh / gunicorn / GitHub Actions / CI 矩阵 / 发版 / GitHub 网络

## 无 Docker 部署（Carapace 体系）

- 一键初始化：`deploy/deploy.sh`（rsync 同步 → venv → alembic → systemd+nginx 安装 → 启动；幂等）
- 常量：APP_ROOT=/opt/perinest（✅ `deploy/deploy.sh:6`）
- 进程守护：Systemd 单元（queen + celery）在 `deploy/systemd/`；Supervisor 备选在 `deploy/supervisord/`
- Nginx：`deploy/nginx/` 三站点（api SSL+限流+动静分离 / wing / leg SPA 回退）
- Gunicorn：`queen/gunicorn.conf.py:4`（UvicornWorker，max_requests 定期回收=断头再生）
- 手册：`deploy/DEPLOYMENT.md`（环境四态 Egg→Nymph→Pupa→Imago）

## CI（`.github/workflows/ci.yml` 四 job）

- queen：MySQL8+Redis7 **services**（CI 平台功能，非项目 Docker 依赖）→ 版本一致性校验 → pip install .[dev] → alembic → pytest（AI_MOCK=true）
- wing/leg：npm ci + tsc+vite build；antenna：npm ci + tsc --noEmit
- **CI 是能力对称原则的执行者**：加端点不登记 PARITY_MAP → queen job 红

## 发版流程（CHANGELOG.md 头部三步）

1. 根 `VERSION` → 同步 `antenna/miniprogram/app.ts` + `queen/pyproject.toml` + 两个 package.json
2. CHANGELOG 加条目（Keep a Changelog 格式）
3. `git tag vX.Y.Z && git push origin main --tags` → `gh release create`（徽章 version 手动改 README 双语）

## 已知环境坑

- 本机到 github.com:443 **间歇性断连**（gh api 可能通而 git push 不通）：push 必须写重试循环，且判断退出码不能经管道 tail（会吞 git 非零码）
- npm 在无 package.json 的目录执行会**向上层目录写包**（污染过 ~ 目录）：新目录先建 package.json
