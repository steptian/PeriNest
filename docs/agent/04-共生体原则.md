# 04 · 共生体原则——AI 是一等公民

**关键词索引**：Symbiont / AI Native / MCP / 权限同源 / 能力对称 / PARITY_MAP / EXEMPT / denied / scope / spiracle / nerve

## 原则定义（v0.6.0 立宪）

> 蜚蠊体内有真实的共生菌群：以宿主摄取的食物为食，替宿主完成消化。
> PeriNest 的 AI 以**授权用户的身份**行事：权限边界=用户边界，能力面=用户操作面。

**AI Native 不是"系统里有 AI 入口"，是 AI 拿到与你相同范围的数据、替你工作。**

## AI 友好五原则（架构文档第 9 章的工程化）

| 原则 | 机制锚点 |
|:---|:---|
| 1. 能力对称 | `queen/tests/test_capability_parity.py:21`（PARITY_MAP 强制对账） |
| 2. 权限同源 | MCP 与 REST 共用 `queen/app/api/deps.py:15` CurrentUser + 同一 service 层 |

| 5. 归属明确 | AI 代下单/反馈落授权用户名下（`queen/tests/test_symbiont.py` 验证） |

## MCP 工具面（7 个 = 用户操作面，`spiracle.py:49` _tool_definitions）

perinest_health / **get_me**（AI 自知替谁工作）/ list_orders（**返回 scope 声明**）/ get_order（越权拒绝）/ create_order（代下单归属本人）/ submit_feedback / ai_chat

## ⚠️ 新增接口的强制流程（违反即 CI 红）

1. 能力 AI 需要？→ 加 MCP 工具 + 登记 `PARITY_MAP`（`queen/tests/test_capability_parity.py:21`）
2. 不需要？→ 登记 `EXEMPT`（同文件 :30）**并写理由（≥8 字，有测试检查理由不敷衍）**
3. 权限逻辑写 **service 层**（REST/MCP 复用一份，禁止端点各自实现）
4. 工具 description 写明权限语义（工具描述=AI 的说明书）
5. 补测试：parity 自动覆盖 + 权限一致性照 `queen/tests/test_symbiont.py:56` 模板

**对称性测试三查**：正向（端点→工具存在）/ 反向（工具→REST 来源，防幽灵能力）/ 全覆盖（OpenAPI 每个用户端点都已"映射或豁免"）。

## 历史教训

- v0.4.0 的 list_orders 工具曾未按用户过滤——普通用户经 AI 可见全库订单（v0.6.0 修复）。**教训：工具复制 REST 逻辑时最易丢的就是权限过滤，所以才要权限逻辑只在 service 层写一份**
- v0.6.x 请求契约 fail-closed 的边界（dsh wire 教训：被静默吞掉的未知字段教运维"开关没用"而非"名字写错"）：`StrictRequest(extra='forbid')` 只加 REST request 模型（`queen/app/schemas/request/__init__.py:5`，测试 `tests/test_request_forbid.py`）。否决了两个扩展面：① response 模型不加——服务端产出无注入风险，forbid 反而让 from_attributes 序列化变脆；② MCP RpcRequest 不加——JSON-RPC 协议面保持宽容，MCP 客户端实现质量参差，协议兼容优先。**原则：fail-closed 用在不可信输入边界，不用在自家产出与协议合同**
